# Project working instructions

- Keep `UPDATES.md` as the append-only project history, as requested by the user.
- Record each work session's implementation changes, documentation changes, validation results, and outstanding limitations there.
- Never delete, replace, or rewrite existing `UPDATES.md` content. Append corrections or superseding decisions in a new dated entry.
- Read `GAME_DESIGN.md`, `CODING_PLAN.md`, and `DEVELOPMENT.md` as needed before changing gameplay. Keep them aligned with implemented behavior; they are living documents, while `UPDATES.md` preserves history.
- Record animation research and experiments in `Animation Testing/LEARNING_LOG.md` as well as the project update log. Keep learning entries append-only and distinguish tested results from proposals; experimental work is not automatically approved for main-game integration.
